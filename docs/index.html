Your own AI assistant,
in its own Proxmox container.

One command on your Proxmox host creates a private, unprivileged LXC running the OpenClaw AI assistant with a full Linux desktop and a real browser — reachable from any browser, and not exposed to your network unless you say so.

bash <(curl -fsSL https://raw.githubusercontent.com/yorch/openclaw-proxmox/main/setup-openclaw-lxc.sh)

Run as root on the Proxmox host. You'll see a plan and confirm before anything is created.

Everything your agent needs, nothing it shouldn't have

OpenClaw runs inside a purpose-built container so you can give it a real desktop and browser without handing it your homelab.

🧱 Contained by design

An unprivileged LXC with nesting. Gateway, desktop and Chrome run as a regular openclaw user — never root, and with no sudo.

🔒 Private by default

Only SSH is reachable. The dashboard and remote desktop sit on loopback until you choose a tunnel, Tailscale, or HTTPS on your LAN.

🖥️ A desktop for your agent

LXQt, Google Chrome and TigerVNC behind noVNC: open the desktop from any browser and watch your assistant work.

🌐 Tailscale, optional

Publish the dashboard and the desktop over HTTPS on your tailnet with real certificates. Token still required; no Funnel, no public exposure.

🔑 SSH keys from GitHub

Type your GitHub username: keys are fetched over HTTPS, validated, shown as fingerprints for you to confirm, and installed. Optionally key-only.

⚙️ Fully configurable

VMID, storage menu, bridge, static IP, VLAN, MTU, DNS, swap, timezone — interactively or entirely from environment variables.

🛡️ Fails loudly

Strict error handling in and out of the container, real health checks at the end, and an offer to clean up a failed run.

♻️ Survives reboots

The container and its three systemd services start with the host. Snapshot before upgrades; destroy to start over.

📦 Batteries included

Node.js 24 from a signed repo, OpenClaw, Homebrew for skills, and the Chrome extension's native host pre-registered.

How it works

The installer is a single Bash script you can read top to bottom. It runs in six stages and ends with a summary you can keep.

  1. Check the host & collect settingsPrompts with sensible defaults, or environment variables for unattended installs. Everything is validated.
  2. Pick storage & templateA menu of enabled storages with free space, the newest Debian 13 template for your architecture, then a plan to confirm.
  3. Create the containerUnprivileged, nesting on, your network settings, starts on boot.
  4. Wait for the networkWaits for an IPv4 address and DNS before touching packages.
  5. ProvisionOne strict script is pushed in and run: user, Node.js, Homebrew, OpenClaw, desktop, Chrome, services. 14 counted steps.
  6. VerifyProbes the gateway, VNC and noVNC over HTTP and ports — not just “service active” — then prints your connection details.

Three ways in — pick your comfort level

The default is the safest. Opt in to convenience when you trust the network.

Default

SSH tunnel

Everything on loopback. Forward two ports and browse locally:

ssh -L 6080:127.0.0.1:6080 \
    -L 18789:127.0.0.1:18789 \
    openclaw@<container-ip>
Recommended for remote

Tailscale Serve

Join your tailnet and get https://<host>.<tailnet>.ts.net for the dashboard and :8443 for the desktop, with valid certificates. Login with an auth key or a link.

ENABLE_TAILSCALE=1 \
./setup-openclaw-lxc.sh
Trusted LAN

HTTPS on your LAN

Serve noVNC at https://<ip>:6080 (HTTPS only, self-signed certificate, random VNC password). The dashboard stays on loopback.

EXPOSE_LAN=1 \
./setup-openclaw-lxc.sh

Security model

An agent that runs commands and browses the web is worth fencing in. Here is exactly how.

LayerChoice
ContainerUnprivileged with nesting — a container escape needs more than a root process inside it.
ProcessesGateway, desktop and Chrome run as openclaw, not root. Chrome keeps its sandbox.
PrivilegesNo sudo for openclaw. Administer from the host with pct enter.
NetworkOnly SSH is reachable by default. noVNC and the gateway stay on loopback; with Tailscale they are published on your tailnet only (no Funnel).
AuthenticationDashboard token is always required, even on your tailnet. Optional GitHub SSH keys with fingerprint confirmation and optional key-only login.
SecretsPassed into the container as private files, never on command lines, and removed afterwards.
Supply chainNode.js from a signed apt repository (no piped installers); versions can be pinned.

Be honest about the limits: the agent can still run commands as openclaw and browse for you, and VNC passwords are capped at 8 characters by the protocol. Put the container on a network segment you are comfortable with.

Configure it your way

Answer the prompts, or preset anything as an environment variable and add --yes for a fully unattended install.

# static IP on a VLAN, bigger disk, GitHub SSH keys
CT_PASSWORD='change-me' \
DISK_SIZE=64 MEMORY=8192 \
IP_ADDRESS=10.20.0.50/24 GATEWAY=10.20.0.1 \
VLAN_TAG=20 GITHUB_SSH_USER=octocat \
./setup-openclaw-lxc.sh --yes

Frequently asked questions

How do I install OpenClaw on Proxmox?

Run the one-line command above as root on your Proxmox host. It asks for a password and a handful of options, shows a plan, and creates an unprivileged Debian 13 LXC with OpenClaw, an LXQt desktop, Chrome and noVNC. It typically takes several minutes.

Is OpenClaw exposed to my network or the internet?

No. By default only SSH is reachable; the dashboard and remote desktop listen on the container's loopback. Reach them through an SSH tunnel, publish them privately on your tailnet with Tailscale Serve, or serve noVNC over HTTPS on your LAN. Tailscale Funnel (public internet) is intentionally not set up.

Why an unprivileged container and a non-root user?

So that a compromised agent or browser does not get root — in the container or on the Proxmox host. Everything runs as openclaw with no sudo, and Chrome keeps its sandbox.

Does it work on ARM or a Raspberry Pi?

Not yet. Google Chrome is installed from its amd64 package, so the installer stops early on other architectures.

Can I use a static IP, a VLAN or a custom bridge?

Yes — pick the bridge from a menu or set BRIDGE, IP_ADDRESS, GATEWAY, NAMESERVER, SEARCHDOMAIN, VLAN_TAG and MTU. Static settings are validated and an address that already answers ping is refused.

How do I log in over SSH with my GitHub key?

Enter your GitHub username when asked (or set GITHUB_SSH_USER). The installer downloads github.com/<user>.keys over HTTPS, validates every key, shows fingerprints for you to confirm and authorizes them for openclaw. Set SSH_DISABLE_PASSWORD=1 for key-only login — keep a way in with pct enter.

Which Proxmox versions are supported?

Proxmox VE 9 is the target. Debian 13 containers need a recent pve-container (6.0.10 or newer has been reported to work); support on PVE 8 is unconfirmed — run apt full-upgrade if pct create rejects the template.

How do I update or remove it?

Update OpenClaw inside the container with npm install -g openclaw@latest and restart openclaw-gateway. Snapshot first with pct snapshot. To remove everything: pct stop <VMID>; pct destroy <VMID> --purge.
